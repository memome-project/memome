Methodology & governance

The trust layer is public by design: schema, validator, evidence rules, governance — all open to inspection and to comment.

★ The 90-day public comment period

Status: checking…

Before the v0.3 freeze, everything is on the table: the entries (IDs, classifications, mitigations) and the processes (governance, promotion criteria, sourcing rubric, naming protocol, dispute process, audit manifest). The pilot already ran six adversarial review rounds; the comment period extends that to the public.

  • Comment on an entry: open an issue or PR citing the source; maintainers apply the promotion criteria and must respond within the published SLA.
  • Comment on process: the period covers the governance documents too. Governance is reviewable, not aspirational.
  • What happens at freeze: accepted changes land in v0.3; rejected proposals get a documented reason; IDs are frozen and the deprecation policy applies from then on.

The evidence-first method

  • Inclusion: ≥3 of 5 operational tests (⇔ ≥1 load-bearing: repeated transmission, adoption/effect, recurrence) — identifiable semantic/behavioral pattern, repeated transmission, adoption or behavioral effect, identifiable transmission mechanism, recurrence across hosts or contexts.
  • Sources: one Source ID = one identifiable evidentiary object. No bibliography placeholders. Real, traceable cases only — no hypotheticals in the pilot corpus.
  • Mechanisms, not judgments: entries describe how information propagates. No ideology judgments, no labeling of ideas as “infectious.”
  • Naming: patterns are named by what propagates — never by the incident, product, CVE, court case, or campaign that evidenced them.
  • Evidence status: every claim carries confidence with defined semantics; contested classifications become assertions, never edit wars.

Schema & validator

The corpus is validator-enforced: a JSON Schema plus consensus rules, and the validator is load-bearing — every schema finding so far came from a real validation failure. Graph-integrity checks (no self-lineage, no cycles, no time-travel, resolved references) land before v0.3. Schema: schema.v0.2-draft.json (CC-BY-4.0). The interventions schema (v0.1-draft, INT- namespace) governs the positive catalog's outcome-first evidence tiers.

Governance

Roles

  • Contributor — anyone: submit entries, propose enums, flag disputes.
  • Coder — pilot: 3–5 independent coders incl. ≥1 LLM, blind-round canonicalization.
  • Maintainer — merges entries, runs the validator, publishes drafts.
  • Dual-use review board — decides redaction and exploitability disputes.
  • Arbiter — final appeal; decisions recorded as provenance.

No single-editor authority over dual-use decisions.

RFC & disputes

  • RFC: propose → 14-day comment (pilot) → vote (maintainer + board, ≥2 distinct supporters) → decision recorded.
  • Dispute: whoever disputes first writes an assertion — no overwrites, no edit wars.
  • Escalation: coding-guide fix after 3 contests; schema change via RFC if the guide can't fix it. SLA published.
  • Deprecation: enum values are never removed silently — deprecated ≥1 release cycle, removed at a version boundary with a migration note.

Dual-use gating

Content is gated when it materially improves replication, targeting, persistence, evasion, or optimization: executable payloads, exact injection strings, reliable propagation recipes, and benchmark details that lower replication difficulty. Every entry carries exploitImpact, requiredAccess, and disclosureStatus (full / partial / redacted / withheld). Redacted material is never pretended away — the ID and a redaction reason stay visible. High-exploitability entries auto-review on a 12-month sunset.

Sandbox policy (firm rule)

The project runs on a local machine while it is read-only analysis and authoring. It must proactively migrate to a sandbox/VM at the first trigger of: downloading or running actual payloads; detection tooling scanning real agent memory or live systems; building the agent sandbox (live agents exposed to cataloged patterns — sandbox by design); or corpus expansion into malware-adjacent territory. This is why the scanner demo is fixture-only and the inoculator is post-launch — publicly and deliberately.
